# فاز ۱ — قرارداد داده و محصول قابل جست‌وجوی استاتیک

## خروجی قابل انتظار
- GitHub Pages از پوشه frontend/ و فایل‌های تولیدشده در frontend/data/ تغذیه می‌شود.
- ویزارد: شهر، کاربری، اسکلت، زیربنا (اسلایدر + عدد)، طبقات روی زمین و زیرزمین، مرحله پروژه.
- مسیر: مشخصات پروژه → موضوعات → جست‌وجوی فارسی → کارت بند → متن، منبع، صفحه و نسخه.
- **تا زمان تأیید شرایط، هیچ مقرره‌ای بر مبنای مشخصات پروژه حذف نمی‌شود.**
- هیچ مدل زبانی، ورود کاربران، دیتابیس آنلاین یا API فعال در زمان استفاده لازم نیست.

## قرارداد داده (قفل نسخه ۱)
فایل data/schema-v1.json چارچوب رکورد نهایی است.
هر رکورد دارای شناسه پایدار ویرایش، id سند، شماره بند و نوع (بند، جدول، تبصره، شکل)، متن اصلی، خلاصه، topic، tags، aliases، key_factors، applicability، references، source، version و review است.

- original_text برای انطباق با PDF بدون بازنویسی حفظ می‌شود. search_text مشتق و نرمال‌شده است، نه جایگزین متن.
- source به منبع رسمی، هش، صفحه PDF و صفحه چاپی (دو مفهوم متفاوت)، وضعیت حق انتشار ارجاع می‌دهد.
- version بین سال چاپ، تاریخ انتشار، تاریخ لازم‌الاجرا شدن، مدرک ابلاغ و وضعیت نسخه تفاوت می‌گذارد.
- applicability.status=not_evaluated یا pending_review: این بند نباید برای هیچ پروژه‌ای قطعی کنار گذاشته شود.
- شناسه‌های بندها در هر نسخه مستقل‌اند؛ ارتباط نسخه قبلی و جدید در revisions آینده قرار می‌گیرد.

## مرز انتشار و صحت
حالا هیچ متن مقرراتی واقعی مجوز نشر/تأیید لازم را ندارد:
- آرشیو ۲۴ PDF ثانویه داخل مخزن خصوصی است. صرف وجود این فایل‌ها **تأیید مقررات یا مجوز نشر** نیست.
- فایل‌های قابل نمایش عمومی فقط از build_static.py به frontend/data/ تولید می‌شوند.
- فقط رکورد با review.status=approved همراه بازبین و تاریخ؛ source.authority=official؛ source.publication_rights=approved؛ هش منبع؛ PDF page و نشانی رسمی؛ version.status=current/historical و در صورت current مدرک تاریخ اجرا، وارد records.json می‌شود. تمام رکوردهای دیگر حذف می‌شوند.
- داده‌های نمایشی از data/fixtures/demo-records.json در demo.json جداگانه هستند، با هشدار آشکار و فاقد عدد مقرراتی واقعی.
- فهرست ۲۴ مبحث از manifest به catalog.json تبدیل می‌شود؛ وضعیت آن catalog_only است نه متن قانون.

## تولید و اجرای سایت
در ریشه پروژه:
- python3 scripts/build_static.py
- python3 -m unittest discover -s tests -p test_static.py -v
- python3 -m http.server 8000 --directory frontend

بعد در مرورگر http://localhost:8000 را باز کنید.

GitHub Actions در pages.yml داده‌ها را تولید، قواعد انتشار را آزمایش و صرفاً frontend را در Pages منتشر می‌کند. اگر Pages برای مخزن خصوصی فعال نباشد، مرحله Deploy ممکن است رد شود. در تنظیمات GitHub > Settings > Pages، Source باید GitHub Actions باشد؛ فعال‌سازی تنظیمات به مجوز اکانت/پلن وابسته است. این Workflow هرگز فایل‌های PDF، کل مخزن یا manifest را به artifact عمومی نمی‌فرستد.
