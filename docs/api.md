# قرارداد API فاز صفر

تمام پاسخ‌های API از نوع JSON با UTF-8 هستند. پیشوند `/api/v1` مستقل از مصرف‌کننده است. در حال حاضر سرور محلی است و هیچ کلید AI یا کلید مصرف کمچه لازم نیست. قرارداد ماشینی: [openapi.json](openapi.json).

| روش | مسیر | رفتار |
|---|---|---|
| GET | `/health` و `/api/v1/health` | زنده بودن فرایند و اتصال DB تنظیم‌شده؛ نبود DB با not_configured مشخص می‌شود |
| GET | `/api/v1/sources` | metadata منابع از DB؛ در اجرای بدون DB فهرست manifest با mode=catalog_only |
| GET | `/api/v1/topics` | فقط موضوع‌های تأییدشده دارای حداقل یک بند تأییدشده از نسخه جاری و سند تأییدشده |
| GET | `/api/v1/search?q=...` | جست‌وجوی قطعی زیررشته literal؛ ۲ تا ۲۰۰ نویسه؛ حداکثر ۵۰ نتیجه؛ بدون AI |
| POST | `/api/v1/project-preview` | اعتبارسنجی مشخصات و بازگرداندن موضوع‌های موجود؛ ذخیره و فیلتر مقررات بر اساس پروژه هنوز پیاده نشده |
| GET | `/openapi.json` | قرارداد OpenAPI 3.1 |

## حالت خالی و خطا

نبود داده یا نبود نتیجه، `items: []` و پیام «داده هنوز بارگذاری نشده» دارد. mode برابر database یا catalog_only است. catalog_only به‌هیچ‌وجه پاسخ از corpus مقررات نیست. سلامت سرور به معنی معتبر و کامل بودن corpus نیست. topics و project-preview مقدار `applicability_status: not_implemented` دارند.

ورودی نامعتبر 400، درخواست بیش از 8192 بایت در project-preview کد 413، اتصال تنظیم‌شده ولی خراب DB کد 503 و مسیر ناشناخته 404 می‌دهد. جزئیات اتصال و گذرواژه در پاسخ خطا نمایش داده نمی‌شود. قرارداد خطا شامل message و در خطای DB، code=database_unavailable است.

## مشخصات پروژه

```json
{"city":"تهران","use":"مسکونی","structure":"فولادی","stage":"طراحی","area":500.25,"floors":3,"basements":1}
```

شهر/کاربری/اسکلت/مرحله باید در frontend/options.json باشند. زیربنا ۱ تا ۱۰۰۰۰۰۰، طبقات روی زمین عدد صحیح ۱ تا ۲۰۰ و زیرزمین ۰ تا ۲۰ است. این مرزها محدودیت فرم‌اند و از مقررات استخراج نشده‌اند. داده پروژه فقط در پاسخ همان درخواست بازگردانده می‌شود؛ `persisted: false`.

## پاسخ آینده بند مستند

وقتی داده تأییدشده وارد شود، search شناسه بند، متن اصلی، locator، pdf_page یک‌مبنا، printed_page، عنوان و نشانی سند، نسخه و سال/تاریخ انتشار ثبت‌شده، تاریخ اجرا و وضعیت قطعیت آن، SHA-256، نشانی PDF رسمی و updated_at رکورد را برمی‌گرداند. تاریخ updated_at تاریخ اصلاح خود مقررات نیست. فیلترهای تأیید در backend/store.py اعمال می‌شوند؛ source URL و locator برای هر نتیجه بازگردانده می‌شوند.

در این فاز pagination، استنتاج شرایط پروژه، پیش‌فرض‌گرفتن تاریخ اجرا، بازنویسی زبان طبیعی، پاسخ صوتی و ارزیابی semantic وجود ندارد. پیش از عرضه عمومی، قرارداد دقیق نسخه‌ها، تاریخچه و کنترل دسترسی تکمیل شود.
