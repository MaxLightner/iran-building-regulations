# فاز ۳-۱ — جست‌وجوی واقعی در متن PDF، بدون انتشار سایت

## هدف کاربر
اعتبارسنجی قانونی و بازبینی علمی هر عدد فعلاً شرط راه‌اندازی جست‌وجو نیست.
بااین‌حال، متن OCR ممکن است اعداد و کلمات را اشتباه بخواند؛
پس همه نتایج با عنوان «متن PDF ـ استخراج اولیه، تأییدنشده» ارائه می‌شوند و
کاربر می‌تواند صفحه سند را باز کند.

## محدوده این مرحله
- استخراج تمام صفحات مبحث ۳ (حریق)، ۵ (مصالح)، ۱۵ (آسانسور و پله‌برقی)؛
  بدون حذف صفحات جلد، فهرست، جدول و شکل.
- استفاده دوباره از متن استخراج‌شده مبحث ۴ و پیوست حفاظتی‌ـ‌انتظامی آن.
- ذخیره هر صفحه با شماره صفحه PDF، متن کامل، روش استخراج، هش منبع و پرچم خطا.
- تولید ایندکس‌های سبک و جداگانه برای هر سند در frontend/data/draft/.
- دسته‌بندی فقط در **۱۰ موضوع اصلی مشترک**، با امکان چند برچسب برای هر صفحه.
  دسته‌بندی خودکار است و ادعای تشخیص الزامات خاص یک پروژه را ندارد.
- جست‌وجوی فارسی داخل متن صفحات، فیلتر مبحث و موضوع، نتایج گروهی،
  نمایش فقط ۸ نتیجه در هر دسته در ابتدا و دکمه «نمایش صفحات بیشتر».
- لینک به PDF هر سند و شماره صفحه آن؛ بدون فرض صفحه چاپی برابر با صفحه PDF.
- ساخت و تست با GitHub Actions؛ **هیچ GitHub Pages deploy انجام نمی‌شود.**

## چرا ۸۴۳ رکورد را در رابط نمایش نمی‌دهیم؟
مبحث ۴ و پیوست آن ۸۴۳ کاندید شماره‌گذاری‌شده بر اساس OCR دارند.
این رکوردها بند قطعی نیستند؛ ممکن است چند بند ادغام یا یک بند تکه‌تکه شده باشد.
این تعداد، منوی سایت نیست. جست‌وجوی فعلی بر اساس صفحه واقعی PDF انجام می‌شود،
و برای کاربر فقط گروه‌های موضوعی / مباحث + صفحه‌های مرتبط نشان داده می‌شوند.

## مرز اعتبار
- «وجود متن PDF» با «تأیید محتوای مقررات» متفاوت است.
- اعداد/جداول OCR همچنان باید در PDF اصلی بررسی شوند.
- نسخه رسمی جاری، تاریخ اجرای مقررات و شروط اعمال به پروژه تأیید نشده‌اند.
- سامانه حق ندارد از جنس کاربری/زیربنا/شهر درباره الزام قطعی نتیجه‌گیری کند؛
  ویزارد مشخصات فعلاً فقط وضعیت پروژه را نگه می‌دارد.
